## Decisions (and why)
- **Postgres می‌ماند** (کاربر اول MySQL خواست، بعد تایید کرد): داده واقعی، pgbouncer، pg_trgm، constraint شرطی.
- رزرو هم‌پوشان اونر **مجاز ماند** (چک تداخل از اولین commit خاموش بوده؛ walk-in عمدی است). فقط قفل گرفته می‌شود.
- `statement_timeout` در کد نه (pgbouncer پارامتر `options` را رد می‌کند) → `ALTER ROLE` موقع دیپلوی.
- `business_id` نامعتبر در تاریخچه پیام = لیست خالی، نه 404 (اپ اونر قبل از لود کسب‌وکار `0` می‌فرستد).
- سقف verify هر IP ۳۰/دقیقه و auth nginx ۱۲۰/دقیقه به‌خاطر CGNAT اپراتورها؛ `token/refresh` از zone auth بیرون.
- تقسیم کار: Haiku جمع‌آوری/تست، Sonnet کد، Opus ممیزی/بازبینی؛ لید (Opus) بازبینی diff و commit.

## Problems / dead ends
- **load test بی‌نتیجه**: `postgres:16-alpine` محلی amd64 است و روی مک emulate می‌شود → خود DB گلوگاه بود (قبل/بعد هر دو ~۴۷ req/s). نسخه قبل با ۲۰۰ کاربر به سقف ۱۰۰ اتصال Postgres خورد.
- اولین چک trigram با `ILIKE` دستی «سبز» بود ولی Django `UPPER(col) LIKE` می‌سازد → ایندکس استفاده نمی‌شد. همیشه EXPLAIN را روی SQL واقعی queryset بگیر.
- zsh متغیرها را word-split نمی‌کند (`env $E` کار نکرد) → `export`.
- Turbopack symlink `node_modules` بیرون از پروژه را رد می‌کند → در worktree `npm ci`.
- پورت 3000 دست یک کانتینر Docker کاربر است؛ روشن کردن Docker Desktop کانتینرهای peyk/hermes/deploy/wordpress را هم بالا آورد.
- ایجنت‌ها بارها با `ECONNREFUSED` قطع شدند؛ با SendMessage از همان‌جا ادامه دادند.
- `git rm` یک ایجنت stage مانده بود و در commit ایجنت دیگر رفت → ایجنت‌ها نباید `git rm`/`add` بزنند.
